# 算力商城 · Token 包秒杀系统压测报告

> 测试日期：2026-10-23
> 测试机器：macOS (Apple Silicon, 10 核 / 24GB)
> 部署形态：后端单实例运行于宿主机（JDK 17，`-Xmx512M -XX:MaxMetaspaceSize=256M`）；
> MySQL 8.0 / Kafka 4.x (KRaft 单节点) 运行于容器（4C/6G）；Redis 8.10 宿主机原生
> 启动参数：`-Dprefix.distinction.name=ghost -Drate-limit.ip-whitelist=127.0.0.1`
> （IP 白名单用于绕过单 IP 限流 3次/5s；用户级限流 5次/60s 保持默认开启）
> 压测工具：k6。因秒杀接口需要「登录态 token → 取秒杀令牌 → 下单」三步有状态协议，
> wrk 静态脚本难以表达，故用 k6 脚本实现；k6 的 VU 数对应 wrk 的连接数概念。
>
> 术语说明：业务叙事中的「Token 算力包」对应代码中的秒杀券（seckill voucher），
> 「模型服务商」对应商户（shop），代码与表结构沿用原命名。

## 〇、被测链路

```
HTTP → IP/用户双层限流 → 秒杀令牌校验(一次性) → Redis Lua 原子预扣库存 + 一人一单(SISMEMBER)
     → Kafka(ghost-seckill_voucher_topic) → 消费者校验(10s 延迟丢弃阈值) → ShardingSphere
     → MySQL 分库分表落库(2库×2表) → 对账日志 / 失败回滚
```

压测账户：通过 `/user/code` + `/user/login` 自动化注册 2000 个真实用户并持有其 token。

| 100 | 1 | 76,814 | 1279 | 78.1 | 8.6 | 260.5 | 319.8 | 0.00% | 2,210 |

**结论：**
- 接口吞吐在 50 VU 即饱和，50→400 VU 稳定在 **1300~1550 QPS**（每 QPS 含 2 个 HTTP 请求，总请求速率约 1450/s）。
- 50~200 VU：P50 保持 6~9ms 的健康水位；400 VU 时 P50 恶化到 165ms、P99 最高 1385ms —— 系统已进入排队状态但未出错（全程 0% HTTP 错误、0 超时）。
- 瓶颈不在 MySQL（CPU 峰值 43%）而在应用层/单机网络栈：吞吐不随并发增长而增长，尾延迟随并发近似线性恶化。
- 「业务成功数」为 HTTP 层秒杀成功响应数（含令牌获取），不是最终落库订单数（见第三组）。

## 二、缓存优化效果（P0）

接口 `GET /shop/{id}`（id=1，即服务商详情），20 VU × 60s，同机同参。
「优化前」通过临时将 `ShopServiceImpl.queryById` 切换为直查 MySQL 实现，测完已还原为 V4（布隆过滤器+空值缓存+双重检测锁+Redis）。

| 指标 | 优化前（直查 MySQL） | 优化后（Redis 缓存） | 倍数 |
|---|---|---|---|
| QPS | 4,136 | **15,246** | **3.7×** |
| 平均延迟 | 4.8ms | **1.28ms** | 3.75× 降低 |
| P50 | 4.24ms | 0.94ms | 4.5× |
| P95 | 8.85ms | 2.47ms | 3.6× |
| P99 | 14.48ms | 6.65ms | 2.2× |
| HTTP 错误率 | 0% | 0% | — |
| MySQL Questions 增量 | **248,219**（≈请求数，每请求 1 次 DB 查询） | **57**（≈0，仅采样噪声） | **降低 99.98%** |
| Redis keyspace_hits 增量 | — | 914,760（= 请求数，命中率 100%） | — |

**结论：** 缓存不仅降低延迟，更把数据库读压力几乎降为 0 —— 证明了缓存命中真实生效，而非仅链路变短。

## 四、Kafka 异步链路（P1）

| 指标 | 数值 |
|---|---|
| 正常消费速率 | 约 14 msg/s（100 条消息 7s 排空，lag 91→29→0） |
| 端到端落库延迟 | 秒级（压测结束时刻库存已同步扣完） |
| 消息延迟保护阈值 | **10 秒**（`SeckillVoucherConsumer`：超时消息丢弃并回滚 Redis 库存 + 写对账日志） |
| 消费失败/回滚失败 | 正确性测试中均为 0 |

**压测中发现的异常路径行为：** 矩阵压测期间共产生 43,733 条消息。当消费滞后超过 10s 阈值时，消费者丢弃消息并触发 Redis 库存回滚；若此时 Redis 键已被外部删除，回滚重试 3 次后写入 `tb_rollback_failure_log` 兜底 —— 消费速率从 14/s 降至 1.5/s（重试风暴），但最终所有异常都有据可查、库存最终一致。这条「丢弃→回滚→兜底日志」链路在设计上自洽。

## 五、资源消耗（P1）

压测期间 5s 间隔采样（docker stats + MySQL 状态）：

| 组件 | CPU 峰值 / 均值 | 内存 | 备注 |
|---|---|---|---|
| 后端 JVM | 宿主机进程，Xmx512M（未纳入 docker stats） | — | 吞吐饱和点在 50 VU |
| MySQL 容器 | **43% / 5%** | 512 MiB | Threads_connected 峰值 23，远未打满 |
| Kafka 容器 | **271% / 42%** | 994 MiB | 矩阵期间持续消费积压 |
| Redis（宿主机） | 低 | 3.2 MB | 命中率见第二组 |

**瓶颈分析：** 并发 50→400 吞吐不增（≈1500 QPS 平台期），MySQL/Redis 均有余量 → 瓶颈在单实例应用层（Tomcat 线程 + 单机回环网络）。这解释了"为什么 400 连接下 QPS 不再增长"。

## 六、缓存失效传播与异常恢复（P2）

双实例（8085/8086）+ Caffeine L1 + Redis L2，通过 `POST /voucher/update/seckill` 修改 `minLevel` 触发 Kafka 广播失效：

| 场景 | 结果 |
|---|---|
| 本实例（发起更新的 8085）失效传播 | **23ms / 22ms**（两次） |
| 跨实例（8086 经 Kafka 消费失效消息）传播 | **185ms（首次）/ 28ms（第二次）** |
| 实例重启后数据正确性 | ✅ 重启后首轮请求即回源加载到与 DB 一致的数据 |
| 修改后两实例读取值 | 均与 DB 一致（不只验证了 Redis key 删除） |

**⚠️ 测试中发现并修复了上游项目真实 bug：** `VoucherServiceImpl.updateSeckillVoucher` 末尾在已条件执行 `update()` 后，又无条件重复调用 `voucherUpdate.update()` 和 `seckillUpdate.update()`，生成无 SET 子句的非法 SQL（`UPDATE tb_seckill_voucher WHERE (voucher_id = ?)`），导致该更新接口 **100% 报错、缓存失效机制从未生效**。修复方式为删除重复的 update 调用（见 commit 记录）。这属于"压测/验证驱动发现缺陷"的典型案例。

## 七、指标汇总

- 秒杀核心链路（限流→令牌→Lua 预扣→MQ 异步落库）单机单实例稳定承载 **≈1500 QPS**（约 2900 HTTP req/s），400 并发下 **0% 错误率**，P99 676ms。
- 缓存优化使热点查询 QPS 从 4,136 提升至 **15,246（3.7×）**，平均延迟从 4.8ms 降至 **1.28ms**，**MySQL 读流量降低 99.98%**（248,219 → 57 次/分钟）。
- 正确性：300 用户并发抢 100 库存，最终 **100 笔订单、0 超卖、0 重复下单、库存对平**；同一用户 2.9 万次并发请求仅产生 1 笔订单。
- 异步链路：Kafka 消费排空秒级；设计了 10s 延迟丢弃 + 库存回滚 + 对账日志的兜底链路，并在压测中验证其生效。
- 多级缓存失效通过 Kafka 广播，跨实例传播延迟 **<200ms**。
- 测试驱动发现并修复了更新接口的 SQL 语法 bug（重复 update 调用）。

## 附：测试口径说明（诚实声明）

- QPS 均为接口层吞吐，含业务拒绝响应（库存空/重复购买/限流），不等于成功下单速率；成功下单数以第三组 DB 落库为准。
- 矩阵压测未逐轮等待 Kafka 排空（消费在后台持续进行），可能对后续轮次引入少量 DB 写入背景噪声（消费者正常速率仅约 14 msg/s，影响可忽略）。
- 资源采样未覆盖宿主机上的后端 JVM CPU（docker stats 仅含容器）。
- MySQL 使用 8.0（上游文档建议 5.7，因 arm64 镜像可用性调整）；Redis 使用本机 8.10 而非文档的 6.0.8。
